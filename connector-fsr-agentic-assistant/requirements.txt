# Pinned to the current majors the box runs (anthropic 1.x, openai 3.x). Both
# moved their transport to httpx2; the box already installed these majors, so
# the floors record what is verified and the upper bounds stop a reinstall from
# silently jumping to the next SDK major underneath our call sites.
anthropic>=1.13,<2
openai>=3.27,<4
pyyaml>=6.0
# The FortiAI proxy provider in fsr-playbooks imports httpx at module level.
# The SDK majors above moved to httpx2 and no longer bring httpx with them, so
# a freshly built box had none and every chat turn on a proxy config failed at
# import. Declared here so the box install does not depend on leftovers.
httpx>=0.27,<1
# Native MCP gateway client (on-box /mcp/* via the mcp SDK streamable-HTTP
# transport). Used by fsr_soc_triage._live_mcp to materialize configured
# connector-op + built-in-MCP-server tools as first-class agent tools.
#
# Now on the 2.x major. 2.0.0 renamed `streamablehttp_client` to
# `streamable_http_client` (our `_streamablehttp_client` accepts either name) and
# moved the client transport to httpx2; the full 2.x stack imports cleanly under
# the box's platform typing_extensions 4.15.0 (no `sentinel` symbol needed), and
# mcp 2.x only requires anyio>=4.9 so the anyio<4.15 cap below still holds. Upper
# bound stays so a reinstall does not jump to a 3.x before it is verified.
mcp>=2,<3
# Upper bound is deliberate and STILL required on mcp 2.x. anyio 4.15 imports
# `typing_extensions.sentinel` and needs typing_extensions>=4.16. The connector
# venv gets 4.16, but the integrations worker has already imported the
# platform's older typing_extensions (4.15.0 on the box, which has no `sentinel`),
# so `import anyio` raises ImportError and every chat turn fails. mcp 2.x only
# requires anyio>=4.9, so 4.14.x satisfies it. Lift the bound only when the
# platform's own typing_extensions carries `sentinel`.
anyio<4.15
